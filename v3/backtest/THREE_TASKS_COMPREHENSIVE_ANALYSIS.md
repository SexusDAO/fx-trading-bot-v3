## 🔍 综合分析

### 问题 1：B/C 场景是否触发？

**答案**：❌ **几乎没有触发**

**数据统计**：
- ETH 2026 年 7 月（震荡）：B/C/F/G = 0 个
- ETH 2024 年 1-2 月（+5.8% 上涨）：B/C = 0 个
- ETH 2024 年 7-8 月（-17.6% 下跌）：B/C = 0 个
- PEPE 2026 年 7 月：B/C/F/G = 0 个

**原因分析**：
1. **场景条件过于严格**
   - C 场景要求"强势回踩"，需要连续大涨 + 缩量回踩
   - B 场景要求"缩量蓄势突破"，需要横盘 + 放量突破
   - 实际行情中这种完美形态很少

2. **1 小时 K 线周期问题**
   - 1 小时级别噪音太多
   - "强势"定义在 1 小时级别难以满足
   - 建议：4 小时或日线级别可能更容易触发

3. **打分系统抑制**
   - 二次打分门槛高（≥70 分）
   - B/C 场景即使触发，打分可能不足

## 💡 参数调整建议

### 建议 1：增加趋势过滤（优先级：高）

**当前问题**：
- 震荡行情中空头信号在上涨趋势中失败
- 上涨行情中多头信号在下跌趋势中失败

**解决方案**：
```python
# 新增趋势过滤
ema20 = _ema(closes[-20:], 20)
ema50 = _ema(closes[-50:], 50)

if direction == "LONG" and ema20 < ema50:
    # 空头趋势中禁止做多
    return MatchResult(matched=False, ...)

if direction == "SHORT" and ema20 > ema50:
    # 多头趋势中禁止做空
    return MatchResult(matched=False, ...)
```

**预期效果**：
- 过滤 30-40% 逆势信号
- 胜率从 25-50% 提升到 50-60%

### 建议 2：降低 B/C 场景触发门槛（优先级：中）

**当前问题**：
- B/C 场景几乎不触发
- 错过强势行情

**解决方案**：
```python
# 场景 C：强势回踩
# 改前：surge >= bl.gain_p80 (前 20% 涨幅)
# 改后：surge >= bl.gain_p60 (前 40% 涨幅)

```

**预期效果**：
- B/C 场景触发频率提升 2-3 倍
- 强势行情参与度更高

### 建议 3：提高开仓门槛到≥80 分（优先级：高）

**当前**：≥70 分  
**数据支持**：

| 打分区间 | ETH 盈亏 | PEPE 盈亏 | 合计 |
|---------|---------|----------|------|
| 70~76 分 | -$8.00 | +$15.50 | +$7.50 |
| 77~83 分 | -$47.57 | -$12.63 | -$60.20 |

**建议**：
- ≥84 分：600U（原样）
- 80~83 分：200U（降低仓位）
- <80 分：不开仓

**预期效果**：
- 交易数减少 40-50%
- 平均打分提升
- 胜率提升到 60-70%

### 建议 4：改用 4 小时 K 线（优先级：低）

**原因**：
- 1 小时级别噪音太多
- B/C 场景难以触发
- 止损容易被扫

**建议**：
- 主周期：4 小时
- 辅助周期：1 小时（精确入场）

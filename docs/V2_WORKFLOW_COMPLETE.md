## 2. 扫描机制：怎么找标的

### 2.1 扫描频率

每 **30 分钟**触发一次全市场扫描（Scanner LLM 任务）。

### 2.2 扫描流程

```
1. 检查熔断器状态（熔断则跳过本轮）
    ↓
2. 判断当前市场模式（BTC 4H EMA + MA99）
    ↓
3. 检查当前持仓数量（达到上限则跳过）
    ↓
4. 拉取候选标的池（涨幅/跌幅/成交量/热度，去重后约90-100个）
    ↓
5. 对每个标的并行分析：
   a. 拉取多周期 K 线（1H×100根 + 4H×100根 + 15M×100根）
   b. 计算技术指标（RSI/EMA/ATR/BB/成交量）
   c. 纯 Python 评分（四向评分体系）
   d. 评分 < 60 → 直接跳过
   e. 评分 60~64 → 观察区（不挂单，记录）
   f. 评分 ≥ 65 → 进入开仓决策
    ↓
6. 开仓决策（见第 5 节）
    ↓
7. 挂单执行（全部限价单，禁止市价）
```

### 2.3 前置过滤（任一触发则直接跳过）

| 检查项 | 跳过条件 | 原因 |
|--------|----------|------|
| 24H 涨跌幅过大 | 涨跌 >50% | 追高风险极大 |
| 流动性 | 24H 成交额 <100万U | 低流动性，滑点大 |
| 成交量枯竭 | 量比 <0.1x | 买卖盘无人，不可信 |
| Token Report 一票否决 | 发现"项目方钱包向交易所转账"、"rug"、"exploit"等关键词 | 风险极高 |
| OI 背离（做多时） | 价格创近期高点 + OI 同期下降 >20% | 多头过热，挂单即爆 |
| 资金费率结算窗口 | 结算前 15 分钟 + 结算后 5 分钟（极端费率>0.5% 延长至30分钟窗口） | 结算窗口主力砸盘猎杀止损 |

## 3. 信号分类：四条路径

通过 `classify_signal()` 函数对标的自动分类，决定走哪条评分路径。

### 路径分类逻辑

```
输入：1H/4H K线 + 资金费率 + 24H涨跌幅

先看跌幅方向：
  24H跌>15% + 资金费率<-0.1% → 尝试逆势多单
    → 有止跌K线 + RSI1H<50 + RSI4H<45 → reversal（逆势多单L2，250U）
    → 极度超卖 RSI4H<25 + RSI1H<35 → reversal_l1（逆势多单L1，125U半仓）

  24H跌>5% + EMA空排 + RSI在35-65中段 → trend_short（趋势空单）

再看涨幅方向：
  24H涨>15% + 资金费率>0.05% → 尝试逆势空单
    → 有见顶K线 + RSI1H>55 + RSI4H>55 → reversal_short（逆势空单L2）
    → RSI4H>80 + BB%超布林上轨 → reversal_short_l1（逆势空单L1）

其余情况 → trend（趋势多单，默认路径）
```

### 四条路径一览

| 路径 | 场景 | 核心条件 |
|------|------|----------|
| `trend` | 趋势多单（默认） | EMA多排，量能跟随 |
| `reversal` / `reversal_l1` | 逆势多单 | 暴跌15%+资金费率负+止跌信号/极度超卖 |
| `trend_short` | 趋势空单 | EMA空排，RSI跌势中段 |
| `reversal_short` / `reversal_short_l1` | 逆势空单 | 暴涨15%+资金费率热+见顶信号 |

### 止跌信号识别

以下任一满足即为"止跌信号"：
- **锤头/下影针**：下影线 > 实体 × 2
- **阳包阴**：当前收盘价 > 前一根开盘价，且当前开盘价 < 前一根收盘价
- **连续 2 根阳线**：最近 3 根 K 线连续上升

### ⚑ 分类层与评分层的语义分离（问题五修复）

`classify_signal()` 只做**路径判断**（是/否的硬性门槛），不做强度量化。
确定路径后，`calc_score_xxx()` 只做**当前路径的信号强度量化**，不重新判断路径。

| 层级 | 使用方式 | 示例 |
|------|----------|------|
| 分类层 | 硬性门槛：RSI4H **是否** < 25 | 是 → reversal_l1；否 → 继续判断 |
| 评分层 | 程度量化：RSI4H **低到什么程度** | <10 得20分；<15 得15分 |

**实现要点**：`classify_signal()` 计算完成后把路径标签作为参数传入评分函数；评分函数不重新计算分类条件，只在确定路径的基础上做强度量化。这样 RSI 小幅波动不会导致标的在两套评分体系之间跳跃。

## 5. 开仓标准：门槛与执行层级

### 5.1 评分分区

| 分区 | 分数范围 | 操作 |
|------|----------|------|
| 直接跳过 | <60 分 | 不做任何记录 |
| 观察区 | 60~64 分 | 记录但不挂单；若分数连续上升 2 次可升仓至正常档 |
| 正常开仓 | ≥65 分（趋势/空单）/ ≥60 分（逆势） | 按层级规则挂单 |

### 5.2 四层入场模式（互斥，按优先级）

| 模式 | 触发条件 | 挂单价格 | 有效期 |
|------|----------|----------|--------|
| **CHASE（追涨）** | 评分≥90 + 刚突破近20根高点 + 量比≥1.5x + RSI<65 | 贴近现价（现价±ATR×0.1以内） | 30 分钟 |
| **DUAL_NET（双网）** | 评分≥85 + 清算密集区充足（>50万U）+ OI充足 | A单：清算区边缘；B单：突破高点+ATR×0.1条件单 | 4 小时 |
| **PULLBACK（回调等待）** | 评分65~84 + 有清算区 | 清算区边缘限价（多单：锚点+ATR×0.2；空单：锚点-ATR×0.2） | 4 小时 |
| **COND_ORDER（条件限价）** | PULLBACK 偏差>阈值 但评分≥60 且偏差<30% | 同 PULLBACK 价格，等价格回调触发 | 4 小时 |
| **WAIT（观望）** | 偏差>30% 或 评分<60 | 不挂单 | — |

> **禁止市价开仓**：任何情况只能用限价单或条件限价单。

### ⚑ DUAL_NET 互斥联动规则（问题二修复）

A 单和 B 单是**同一机会组的两个互斥方案**，不是叠加仓位。系统在内部用 `opp_group_id` 标记两者属于同一组。

```
挂单时：同时挂出 A 单（限价）和 B 单（条件限价），标记同一 opp_group_id

A 单成交 → 立刻自动撤销 B 单，仓位按 A 单确认
B 单成交 → 立刻自动撤销 A 单，仓位按 B 单确认
两单均未成交 → 有效期到期统一撤销
```

**B 单触发价格定义**：近20根K线高点 + ATR×0.1（代表"有效突破"而非噪音）

**止损分别计算**：
- A 单止损：基于 A 单入场价，从清算区外侧计算
- B 单止损：基于 B 单入场价（更高），止损相应上移，保持相同的 ATR 倍数距离

**仓位关系**：A 单和 B 单仓位相同（非叠加），满足仓位上限时以第一个成交的为准。

## 6. 入场位置：如何确定限价单位置

### 6.1 多源锚点竞选（四个来源）

系统综合四个来源确定支撑/压力锚点，选距现价最近且合理的一个：

| 来源 | 权重 | 说明 |
|------|------|------|
| **Coinglass 清算密集区** | 最高（×0.85） | 真实多/空头爆仓聚集区，最有意义 |
| **订单簿最大挂单墙** | 高（>50万U时采用） | 反映当前市场挂单意愿 |
| **近100根K线成交密集区** | 中（×0.8） | 价格×成交量热力图最集中点 |
| **近20根K线低点中位数** | 辅助（×0.75） | 比最低值更稳健，避免插针拉偏 |
| **MA25 / MA99 均线** | 辅助（×0.7） | 均线支撑兜底 |

**选择规则**：偏离现价 0.3%~10% 范围内，选最近的一个锚点。

### 6.2 多单入场锚点

```
综合权重：
  Coinglass 清算区 (liq_below)   权重 3
  订单簿买单墙 (ob_support)       权重 2
  K线低点中位数 (kline_mid20)     权重 1

入场价 = 加权均价 + ATR×0.2（贴近锚点上方，提高成交概率）

特殊：清算区与买单墙价差≤0.5% → 取两者均值（共振点，支撑力最强）
```

### 6.3 空单入场锚点

```
综合权重：
  Coinglass 清算区 (liq_above)    权重 3
  订单簿卖单墙 (ob_resistance)    权重 2
  K线高点中位数 (kline_mid20)     权重 1

入场价 = 加权均价 - ATR×0.2（贴近锚点下方）
```

### 6.4 山寨币专属路径（ATR/价格 >6%）

| 路径 | 触发条件 | 入场价 |
|------|----------|--------|
| **CHASE_ALT（暴拉后追空）** | 24H涨≥15% + 从高点回落≥5% + RSI>55 + 量比萎缩 | 现价 - ATR×0.1 |
| **FADE（高位减速做空）** | RSI≥75 且 BB%≥85（极度超买顶部） | 现价 + ATR×0.3（等小反弹） |

## 7. 止盈止损：Coinglass 清算区锚定

> **核心原则**：止盈止损必须锚定 Coinglass 真实清算密度分布，禁止使用订单簿买单墙或固定 ATR 倍数作为唯一依据。

### 7.1 止损规则

**多单止损**：
```
1. 调用 coinglass_api.get_liq_zones(sym) 获取下方真实清算密集区
2. sl_price = 下方最远清算密集区 - ATR × sl_mult
   （sl_mult 动态：ATR/价格>15% → 2.0；8-15% → 1.5；<8% → 1.2）
3. 安全检查：sl_price 不能高于入场价（否则 sl = 入场价 - ATR × sl_mult）
```

**空单止损**：
```
1. sl_price = 上方所有清算密集区的外侧（不能落在密集区内侧！）
2. 公式：sl = 上方最远清算密集区 + ATR × 0.5
3. 安全检查：sl_price 不能低于入场价
```

**止损强制规则**（来自 AKE/CBRS 实战教训 2026-07-25）：
- ❌ 禁止止损锚在清算密集区**内侧**（价格小反弹即误扫，然后遇压力回落，白白亏损）
- ❌ 禁止用订单簿买单墙作为止损锚点（买单墙可撤单，不稳定）
- ✅ 必须用 `coinglass_api.get_liq_zones()` 确认清算区外侧

### 7.2 止盈规则

**分批止盈（60% + 40%）**：
```
TP1（60%仓位）= 方向内最近的清算密集区前沿 + ATR×0.1 缓冲
TP2（40%仓位）= 方向内密度最大的清算密集区
```

**止盈强制规则**（来自 AKE 实战教训 2026-07-25）：
- ❌ 禁止 TP 落在两个清算密集区之间的**真空带**（等不到成交）
- ✅ TP1 必须锚定最近的清算密集区前沿
- ✅ 开仓成交后 5 分钟内用 Coinglass 复核止盈位

### 7.3 完整止损止盈计算示例

```python
# 多单示例
```

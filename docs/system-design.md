## 一、系统总体目标

全自动化合约交易系统，Binance USDT 合约主账号：
- 全仓模式，50x 杠杆，单笔名义仓位 250~1000U
- 最多 5 个同时持仓（多单 ≤3，空单 ≤1）
- 无需人工干预，异常时推送通知
- **禁止市价单开仓**（只用于止损/轧空/熔断平仓）

## 二、完整开仓流程（14步）与模块对应

```
扫描信号
 ↓
第一步：信号方向 + 评分          ← classify_signal + calc_score_*
第二步：找入场位置               ← calc_entry_mode（P1重构）
第三步：环境过滤                 ← market_filter()（P2新建，统一入口）
第四步：风控前置                 ← pre_order_gate()（P1新建，统一关卡）
第五步：仓位大小                 ← calc_position_size()（P1新建，统一计算）
第六步：最终确认                 ← pre_order_gate()最后一关
第七步：挂单执行                 ← place_entry_order()
 ↓
成交
 ↓
第八步：止损止盈设置 ← 同步、即时（P0修复，不再延迟）
第九步：补仓条件预设             ← check_add_position()（P2新建）
第十步：持仓监控启动             ← gates注册 + patrol入队 + 状态确认（P3完善）
 ↓
持仓中
 ↓
第十一步：动态止损跟随 ← WS实时  ← price_gates（现有，保留）
第十二步：结构健康检查 ← 30分钟  ← patrol_loop 双层（P2升级）
 ↓
平仓条件触发
 ↓
第十三步：平仓执行               ← algo止损 + preempt（现有）
 ↓
第十四步：平仓后处理 ← 立刻触发  ← _on_close_filled（现有，P3完善日志）
```

## 四、P0：立刻修（影响资金安全）

### P0-1：止损挂单从延迟改为即时同步

**现状**：`_on_open_filled` 里 `time.sleep(3)` 后才挂止损。
**风险**：3秒裸仓，急速行情可能直接穿越止损价。

**修复方案**：
```
_on_open_filled() 执行顺序（强制，不可打乱，不可并发）：
  Step 1：挂止损单（同步）
           失败 → 重试3次（每次间隔1秒）
           3次全败 → 市价平仓 + 推送告警
  Step 2：确认止损单已在交易所生效
  Step 3：注册 price_gates
  Step 4：写入 pos_state（通过 _ps_store）
  Step 5：挂止盈单（可异步，不阻塞主流程）
  Step 6：推送成交通知
  Step 7：其他后续逻辑（补仓预设、日志等）
```

**关键**：止损挂单前置，不等 Coinglass 数据（Coinglass 查询耗时 1~3秒，会导致裸仓）。止损价来源优先级：
1. pos_state 里已预写的 `hard_sl`（scanner 挂单时写入）
2. ATR × 系数快速计算（不需要 API）
3. 入场价 × 固定比例兜底（最慢路径，最差情况）

### P0-2：持仓监控启动时间窗口消除

**现状**：gates 注册和 patrol 之间有3秒窗口。
**修复**：开仓成交后按严格顺序执行（见 P0-1 方案），gates 注册在止损挂单之后立即执行，不延迟。

## 五、P1：优先修（影响成交率）

### P1-1：入场位置完整重构（第二步）

**动态搜索范围**：
```
基础范围 = ATR(14) / 现价 × 100%

布林带系数：BB宽度<5% → 0.8；5~15% → 1.0；>15% → 1.3
量能系数：  量比<0.5 → 0.9；0.5~1.5 → 1.0；>2.0 → 1.4
币种系数：  BTC/ETH/SOL/BNB → 0.7；中等 → 1.0；小币 → 1.3

最终范围 = 基础范围 × 三系数相乘
保护：最小1%，最大15%
```

**多源锚点竞选**（按优先级）：
1. Coinglass 清算密集区（要求清算量 >50万U）
2. 近100根K线成交密集区（价格热力图）
3. 前低/整理区间下沿
4. MA25/MA99 均线支撑

选择：距现价最近且在动态范围内的锚点。

**信号强度 × 清算区入场矩阵**：

| 场景 | 评分 | 清算区 | 入场方式 | 仓位 | 有效期 |
|------|------|--------|----------|------|--------|
| 一 | ≥80 | 无 | 1/3/5m支撑位挂限价；找不到则贴现价ATR×0.3 | 正常 | 30min |
| 二 | ≥80 | 有 | 清算区边缘限价（多挂下沿，空挂上沿） | 正常 | 4h |
| 三 | 60~79 | 无 | 进观察区，不挂单 | - | - |
| 四 | 60~79 | 有 | 清算区边缘限价 | 减半 | 2h |
| - | <60 | - | 跳过 | - | - |

场景四成交后：若评分升到≥80 → 触发补仓至正常仓位。

### P1-2：仓位大小统一（第五步）

**新建 `calc_position_size(sig_type, score, btc_trend, recent_losses)` 函数**，全系统统一调用：

```
趋势多单：
  60~69分 → 300U
  70~79分 → 500U
  80~89分 → 700U
  ≥90分   → 1000U

趋势空单：
  60~69分 → 300U
  70~79分 → 450U
  ≥80分   → 600U

逆势多单：250U（L2级别）/ 125U（L1级别）
逆势空单：250U（L2级别）/ 125U（L1级别）
场景四减半：以上数值 × 50%

动态调整系数（相乘）：
  BTC顺势：× 1.2
  BTC逆势：× 0.8
  连续亏损3笔：× 0.8
  连续亏损5笔：暂停开仓（返回0）
```

### P1-3：统一最终确认关卡（第四/六步）

**新建 `pre_order_gate(sym, direction, score, funding, pos_size)` 函数**，按序检查7项：

```
检查一：持仓上限     多单<5 且 空单<1
检查二：熔断状态     当日亏损<50U
检查三：黑名单       该币种不在黑名单
检查四：同币种限制   该币种无持仓/挂单
检查五：总仓位上限   当前名义+新仓位 < 余额×2.5
检查六：聪明钱方向   方向一致或中性（明确反向→强制拒绝）
检查七：资金费率     多单<+0.5%；空单>-0.3%

全部通过 → {"ok": True}
任一失败 → {"ok": False, "reason": "..."}，记录日志
```

## 六、P2：重要（影响持仓质量）

### P2-1：结构健康检查升级（第十二步）

**patrol_loop 改为双层**：

```
第一层（原有，每3分钟）：
  检查止损止盈是否存在
  缺失则补挂

第二层（新增，每30分钟）：
  对持仓币种重新运行评分
  评分 ≥60     → 继续持有
  评分 40~59   → 降低止盈目标，准备离场
  评分 <40     → 主动平仓
  出现反向信号  → 立刻平仓
  聪明钱出货    → 立刻平仓
  入场逻辑破坏  → 立刻平仓
```

### P2-2：补仓完整闭环（第九步）

**新建 `check_add_position(sym)` 函数**：

触发条件（全部满足）：
- 浮亏 >3%
- 结构健康评分 ≥60
- 该仓位补仓次数 <2
- 距上次补仓 >30分钟

执行流程：
1. AI判断支撑位，计算补仓价
2. 补仓仓位 ≤ 首仓大小
3. 挂补仓限价单（不用市价）
4. 成交后更新均价
5. 根据新均价重新计算止损位
6. 更新 Algo 止损单
7. 记录补仓日志

场景四补仓升级：成交后评分升到≥80 → 补仓至正常仓位（差额补齐）。

### P2-3：环境过滤统一（第三步）

**新建 `market_filter(sym, direction, score)` 函数**，返回调整后评分：

```
过滤一：BTC趋势
  明显上涨 → 多单+5，空单-10
  明显下跌 → 空单+5，多单-10
  横盘     → 不调整

过滤二：时段
  北京时间 21:15~22:30（美股开盘）→ -10
  UTC 02:00~06:00（低流动性）     → -10

过滤三：资金费率结算窗口
  结算前后30分钟 → 暂停开仓（返回-999）

过滤四：恐慌贪婪指数
  FGI <20（极度恐慌） → 禁止做空
  FGI >85（极度贪婪） → 禁止做多
```

## 七、P3：完善（提升系统稳定性）

### P3-1：交易日志完整化（第十四步）

`trade_logger.py` 每笔记录字段：
- 币种/方向/信号类型（trend/reversal/...）
- 入场时间/价格/仓位大小
- 平仓时间/价格/盈亏（U + %）
- 平仓原因（止损/止盈1/止盈2/主动/熔断）
- 入场时评分明细
- 入场时BTC趋势/资金费率
- 是否触发补仓/次数

统计功能（每日汇总）：
- 按信号类型统计胜率
- 按时段统计胜率
- 按币种统计盈亏
- 连续亏损笔数（触发降仓保护）

### P3-2：动态黑名单

```
自动规则：
  同一币种连续亏损2次 → 加入7天黑名单
  黑名单期间扫描时自动过滤
  7天后自动解除

手动黑名单：永久有效，不自动解除
```

### P3-3：持仓监控确认机制（第十步）

开仓成交后输出监控状态确认（写入日志+推送）：
```
[开仓确认] BTCUSDT LONG
  ✅ 止损单：algo #12345678 @63000
  ✅ gates：已注册（sl=63000，tp1=68000）
  ✅ patrol：已加入监控队列
  ✅ pos_state：已写入
  ✅ 止盈单：TP1 @68000，TP2 @71000
全部就绪，开仓完成
```
任意一项失败 → `⚠️` 告警推送。

## 八、P4：优化（提升信号质量）

### P4-1：B单量比改为实时数据

**现状**：30分钟缓存，新币/急拉行情量比失真。
**修复**：WS 订阅1H K线实时推送（ws_monitor 已有 `handle_kline_1h`），当根成交量实时更新。量比判断加绝对量兜底：1H成交量>200M USDT → 视为量能充足，不受量比限制。

### P4-2：撤单冷静期

**现状**：挂单后11分钟可能因短期评分波动撤单。

**修复**：
```
挂单后30分钟冷静期：
  评分跌破50才撤（现在是60）
  不因短期波动撤单

30分钟后恢复正常逻辑：
  评分跌破60 → 撤单
  出现强反向信号 → 撤单
```

### P4-3：条件限价单替代WAIT

**现状**：锚点偏离过大 → WAIT，直接跳过。
**修复**：偏离过大时不跳过，改为挂条件限价单（等价格回来自动触发），4小时有效期，评分下滑或反向信号时撤单。（已有 COND_ORDER 模式，完善触发逻辑即可）

## 九、P5：长期优化（系统智能化）

### P5-1：复盘反馈机制

每周分析 trade_logger 数据：
- 信号类型胜率 <40% → 自动降低该类信号评分权重
- 时段胜率低 → 自动降低该时段评分加成
- 币种反复亏损 → 自动加权降低评分

### P5-2：市场周期自适应

```
自动判断市场周期（基于BTC趋势+FGI+资金费率综合）：
  牛市：多单仓位上限提升，空单降低
  熊市：空单优先，多单降仓
  震荡：逆势单优先，趋势单降低
```

### P5-3：配置热更新

`strategy-config.json` 变化后自动 reload，不重启机器人（`config_watcher.py` 已有框架，补全监听逻辑即可）。
